# 41 Table admission

Messages between a client and a table from table selection up to the game
initializer, for a human table and for the Computer menu. Ordinary tables
are run by the [room service](../services.md#room-service); event tables by
the event match service. The body after the header is `@Section=/key=value`
text of at most 447 bytes, see [envelope.md](../envelope.md). The order of
these messages is in
[match-admission.md](../../flows/match-admission.md) and
[event-matches.md](../../flows/event-matches.md#sequence); turn
messages (43/07 onward) are in [43.md](43.md).

## 41/01 GameEN

| Direction | Service | Argument | Reply | Body |
| --- | --- | --- | --- | --- |
| C2S | room service, or to the event match service on an event table | 0 | [41/02 GameEA](#4102-gameea) | `struct AdmissionIdentity` |

```c
struct AdmissionIdentity {
    uint64_t NN;     // sixteen hex digits, the account's nickname identity
    uint32_t HID;    // POL handle slot, independent of the character; the client sends 0
    uint32_t Dm;     // profile directory number
    uint32_t Vol;    // profile volume number
    uint8_t  CN[16]; // character name, hex bytes
    uint8_t  HN[31]; // handle name, hex bytes
    uint32_t L;      // locale
};
```

`GameEN` and [41/12 GameENC](#4112-gameenc) carry this body; [01 Req](01.md)
carries the same fields plus `Tm0` and `Tm1`.

### Room service

```
C2S GTM0G41000100@GameEN=/NN=0000000000000001/HID=0/Dm=0/Vol=0/CN=416C696365/HN=416C696365/L=1
```

Sent by a human claiming an empty table or joining an open one. A server
authenticates on the connection, not on these fields; it should require
`NN` and `CN` to match the authenticated account and ignore `HID` as a
character selector.

### Event match service

```
C2S GTM0G41000100@GameEN=/NN=0000000000000001/HID=0/Dm=0/Vol=0/CN=416C696365/HN=416C696365/L=1
```

Sent to the event table after the client accepted a
[D2/00 MuchMake](D2.md#d200-muchmake) offer and received
[D2/01 Start=1](D2.md#d201-muchmake-start). The table must already be
published as an `A` record before `GameEN` arrives.

## 41/02 GameEA

| Direction | Service | Argument | Reply | Body |
| --- | --- | --- | --- | --- |
| S2C | room service or event match service to the requester | 0 | none; the owner continues with [14 Apply](14.md), a joiner waits for the roster | `struct GameEA` |

```c
struct GameEA {
    int32_t EN;   // 1 admits the claiming owner, 2 a joiner; negative values are refusals, see the table below
};
```

### Room service

```
S2C GTM0G41000200@GameEA=/EN=1
```

The example is constructed from the field list; no capture of it is recorded
(unverified).

`EN=1` sends the client into the owner's settings editor without debiting
the wager; the owner subtracts its chosen wager locally just before sending
[14 Apply](14.md). `EN=2` takes the existing-table route and subtracts the
cached advertised wager locally. `VsGameInit /M` then overwrites the local
balance, so a server that debits at start should send post-debit balances
there.

The client discards any queued 41/04 and 41/07 when it receives `GameEA`; a
server must send the roster and a pending start offer only after admission
has completed, see
[match-admission.md](../../flows/match-admission.md#rules).

Negative `EN` values the client maps to its own text:

| Reply | Meaning |
| --- | --- |
| `EN=-32870` | Table full |
| `EN=-32871` | Not ready |

The `GameEA` token is also the body of [41/0E](#410e-gameea-exit).

### Event match service

```
S2C GTM0G41000200@GameEA=/EN=1
```

The example is constructed from the field list; no capture of it is recorded
(unverified).

Every event participant receives `EN=1`; there is no owner and no settings
editor on this path. The client then JOINs the table channel and sends
[01/00 Req](01.md#0100-req). A cancelled admission is answered with
`41/10 @GameWa=/Error=-1`.

## 41/03 GameM

| Direction | Service | Argument | Reply | Body |
| --- | --- | --- | --- | --- |
| C2S | room service | 0 | [41/04 GameML](#4104-gameml) with `/ID=` | `struct GameM` |

```c
struct GameM {
    uint64_t ID;          // empty in a roster query
};
```

```
C2S GTM0G41000300@GameM=/ID=
```

A roster query that may be sent at any time.

## 41/04 GameML

| Direction | Service | Argument | Reply | Body |
| --- | --- | --- | --- | --- |
| S2C | room service to the table members | 0 | none | `struct GameML` |

```c
struct GameML {
    uint64_t ID;          // table identity; present only when answering a GameM query
    uint32_t Num;         // member count
    uint8_t  MLNN[3][16]; // member names, hex bytes, `|` separated
    uint64_t MLID[3];     // member identities, `|` separated
    uint32_t Po[3];       // 0 in the known implementation (unverified)
    uint32_t Lv[3];       // collection points (unverified)
    uint32_t Rk[3];       // rating
    uint8_t  HN[3][16];   // handle names, hex bytes, `|` separated
};
```

```
S2C GTM0G41000400@GameML=/ID=0000000000000001/Num=2/MLNN=416C696365|426F62/MLID=0000000000000001|0000000000000002/Po=0|0/Lv=15|20/Rk=300|300/HN=416C696365|426F62
```

`GameML` with `/ID=` answers a `GameM` query; without it, it is the roster
push that follows a `TD` delta, before [1A GameOwner](1A.md). The same
fields form the `GameML` section of [02 PLAYACK](02.md#0200-playack). The
client keeps `MLNN` and `HN` in 16-byte terminated fields, so a server must
not send names longer than 15 bytes.

## 41/05 GameQT

| Direction | Service | Argument | Reply | Body |
| --- | --- | --- | --- | --- |
| C2S | room service | 0 | [41/06 GameQA](#4106-gameqa) | `struct GameQT` |

```c
struct GameQT {
    uint64_t ID;          // absent when the sender quits; the member to remove when the owner sends it
};
```

```
C2S GTM0G41000500@GameQT=
C2S GTM0G41000500@GameQT=/ID=0000000000000002
```

`@GameQT=` with no field quits the table; `@GameQT=/ID=` from the owner
names another member to remove.

## 41/07 Start offer

| Direction | Service | Argument | Reply | Body |
| --- | --- | --- | --- | --- |
| S2C | room service to the other humans | 0 | [01 Req](01.md#0100-req) to accept, [41/0F GameNG](#410f-gameng) to decline | none |

```
S2C GTM0G41000700
```

A server sends it when the owner sends
[41/0A GameReady](#410a-gameready). The client discards a queued 41/07 when
it receives `GameEA`, so a server must not send it to a guest whose
admission is still in progress.

## 41/08 GameOK

| Direction | Service | Argument | Reply | Body |
| --- | --- | --- | --- | --- |
| C2S | room service, or to the event match service on an event table | 0 | [41/09](#4109-start-confirmation) once every seat has sent it | none |

### Room service

```
C2S GTM0G41000800@GameOK=
```

Each human sends it after a positive `PLAYACK`; it accepts the `Tet` and
`Tab` carried by that `PLAYACK`.

### Event match service

```
C2S GTM0G41000800@GameOK=
```

Sent after `PLAYACK`. No `41/0A GameReady` precedes it on the event path.

## 41/09 Start confirmation

| Direction | Service | Argument | Reply | Body |
| --- | --- | --- | --- | --- |
| S2C | room service or event match service to all humans | 0 | none | none |

### Room service

```
S2C GTM0G41000900
```

A server sends it once every seat has sent `GameOK`, then
[43/01 VsGameInit](43.md#4301-vsgameinit).

### Event match service

```
S2C GTM0G41000900
```

Sent to every participant after the last `GameOK`; the server then starts
the round with [43/01 EventGameInit](43.md#4301-vsgameinit) instead of
`VsGameInit`.

## 41/0A GameReady

| Direction | Service | Argument | Reply | Body |
| --- | --- | --- | --- | --- |
| C2S | room service | 0 | none to the owner; [41/07](#4107-start-offer) to the other humans | none |

```
C2S GTM0G41000A00@GameReady=
```

The owner's start offer. The server relays it as 41/07 to the
other humans.

## 41/0C GameKick

| Direction | Service | Argument | Reply | Body |
| --- | --- | --- | --- | --- |
| S2C | room service to all members | 0 | none | `struct GameKick` |

```c
struct GameKick {
    uint32_t Kick;        // empty, purpose unknown (unverified)
    uint32_t FN;          // empty, purpose unknown (unverified)
    uint32_t QN;          // empty, purpose unknown (unverified)
    struct GameML list;   // the roster, as in 41/04
};
```

```
S2C GTM0G41000C00@GameKick=/Kick=/FN=/QN=/Num=.../MLNN=.../MLID=.../Po=.../Lv=.../Rk=.../HN=...
```

Sent after an owner's `GameQT=/ID=`. `Kick`, `FN` and `QN` are empty in the
known implementation (purpose unknown, unverified); the rest is the
`GameML` body. The kick itself is a server choice and the notice shape is
the known implementation's.

## 41/10 GameWa

| Direction | Service | Argument | Reply | Body |
| --- | --- | --- | --- | --- |
| S2C | room service to all members | 0 | none | `struct GameWa` |

```c
struct GameWa {
    int32_t Error;        // -1, the start is cancelled
};
```

```
S2C GTM0G41001000@GameWa=/Error=-1
```

`Error=-1` cancels the start. A server sends it after a `GameNG`, optionally
to the others after a [20 ExitCh](20.md), and to cancel an event admission.

## 41/13 GameECA

| Direction | Service | Argument | Reply | Body |
| --- | --- | --- | --- | --- |
| S2C | room service to the requester | 0 | none; the client continues with [2D CheckJoinTable](2D.md) | `struct GameECA` |

```c
struct GameECA {
    int32_t EN;   // 1 admits; -32871 is mapped by the client to "Computer entry not ready"
};
```

```
S2C GTM0G41001300@GameECA=/EN=1
```

After `EN=1` the client PARTs the room channel and continues with
[2D CheckJoinTable](2D.md) and [01 Req](01.md); it then waits for
[43/02 ComGameInit](43.md#4302-comgameinit). There is no `GameOK` and no
`VsGameInit` on this route.
