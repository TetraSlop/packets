# 13 Rule reply

The answer the [room service](../services.md#room-service) gives to
[12 Rule](12.md): the table's current game rules and table options. The
settings editor that reads it is in
[tables.md](../../flows/tables.md#sequence).

## 13/00 Tet and Tab

| Direction | Service | Argument | Reply | Body |
| --- | --- | --- | --- | --- |
| S2C | room service to the querying client | 0 | none | `struct RuleReply` |

```c
struct RuleReply {
    struct {
        uint32_t bm;      // wager, 0..2000
        uint8_t  du;      // double-up flag
        uint8_t  st;      // special tiles flag
        uint8_t  cb;      // cb tiles flag
        uint8_t  ca;      // spinners flag
        uint8_t  gs;      // departure rule, 0..2
        uint8_t  tl;      // time limit, 0..5
    } Tet;                // game rules
    struct {
        uint8_t  in;      // observe setting, 0..2
        uint32_t lu;      // upper collection-point bound
        uint32_t ll;      // lower collection-point bound
        uint32_t au;      // upper rank bound, 300
        uint32_t al;      // lower rank bound, 100
        uint8_t  co;      // comment index, 0..8
        uint8_t  pa;      // 1 when a password is set
        uint8_t  pw[12];  // password as hex byte pairs, present only when set
    } Tab;                // table options
};
```

```
S2C GTM0G13000000@Tet=/bm=0/du=0/st=0/cb=0/ca=0/gs=1/tl=2@Tab=/in=1/lu=99999/ll=0/au=300/al=100/co=4/pa=0
```

`Tet` and `Tab` have the member layout of the same sections in
[24 Save](24.md). The client matches the sender against its table directory,
stores the fields in that table's cache and shows them in the settings
editor. The saved personal defaults are untouched. A password, when set,
appears as `/pw=` hex in `Tab`.
