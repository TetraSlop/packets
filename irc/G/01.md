# 01 Req

The start request every human sends to its table once it is ready to play.
The table is run by the [room service](../services.md#room-service), or by
the event match service for an event table. On a human table it follows the
start offer; on the Computer route it follows `GameECA` and
`CheckJoinTable`. The handshakes that lead to it are in
[match-admission.md](../../flows/match-admission.md) and
[event-matches.md](../../flows/event-matches.md#sequence).

## 01/00 Req

| Direction | Service | Argument | Reply | Body |
| --- | --- | --- | --- | --- |
| C2S | room service, or to the event match service on an event table | 0 | [02/00 PLAYACK](02.md#0200-playack) | `struct Req` |

```c
struct Req {
    uint64_t NN;     // sixteen hex digits, the account's nickname identity
    uint32_t HID;    // POL handle slot, independent of the character; the client sends 0
    uint32_t Tm0;    // purpose unknown (unverified); observed 0
    uint32_t Tm1;    // purpose unknown (unverified); observed 0
    uint32_t Dm;     // profile directory number
    uint32_t Vol;    // profile volume number
    uint8_t  CN[16]; // character name, hex bytes
    uint8_t  HN[31]; // handle name, hex bytes
};
```

`NN`, `HID`, `Dm`, `Vol`, `CN` and `HN` are the same fields the client sends
in [41/01 GameEN](41.md#4101-gameen).

### Room service

```
C2S GTM0G01000000@Req=/NN=0000000000000001/HID=0/Tm0=0/Tm1=0/Dm=0/Vol=0/CN=416C696365/HN=416C696365
```

On a human table each human sends `Req` after the start offer and waits for
`PLAYACK`. On the Computer route the client sends `Req` before the table
channel JOIN completes and polls `PLAYACK` once, ignoring the result. A
spectator sends the same `Req` after `CheckJoinTable`, see
[spectators.md](../../flows/spectators.md).

### Event match service

```
C2S GTM0G01000000@Req=/NN=0000000000000001/HID=0/Tm0=0/Tm1=0/Dm=0/Vol=0/CN=416C696365/HN=416C696365
```

Sent to the event table after the table channel JOIN that follows
`41/02 @GameEA=/EN=1`. The `Tet` and `Tab` of the `PLAYACK` must agree with
the published `A` record, because `EventGameInit` does not reset `bm` and
`du`. An observer of an event table sends the same `Req` and is answered
with the first seat's `PLAYACK`.
