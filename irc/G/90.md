# 90 Event cards request

90 asks the [event card service](../services.md#event-card-service) of an
event room to open the card collection screen, where the client receives
the cards and money an event awarded it. The service answers with
[91/00 CardEnt](91.md#9100-cardent). The whole visit is in
[event-cards.md](../../flows/event-cards.md).

## 90/00 CardReq

| Direction | Service | Argument | Reply | Body |
| --- | --- | --- | --- | --- |
| C2S | event card service | a sequence number chosen by the client; the reply echoes it | [91/00 CardEnt](91.md#9100-cardent) | `struct CardReq` |

```c
struct CardReq {
    uint64_t NN;          // account identity, 16 hex; must match the authenticated account
    uint32_t HID;         // POL handle index, must fit 32 bits
    uint32_t Dm;          // profile directory number, must fit 8 bits
    uint32_t Vol;         // profile volume number, must fit 16 bits
    uint8_t  CN[16];      // character name, hex; must match the account
};
```

```
C2S GTM0G90000001@CardReq=/NN=0123456789ABCDEF/HID=0/Dm=1/Vol=1/CN=416C696365
```

The client sends the request from inside the event room and shows at most
nine cards per visit. It never starts a match through this service. A
server answers with [91/00 CardEnt](91.md#9100-cardent) and, on a positive
answer, follows with [B2/13 EcmInit](B2.md#b213-init).

Server choice: a server requires an existing event member and
an enabled service, denies excluded or busy accounts, and lets existing
members collect after the event end.
