# 02 PLAYACK

The answer the [room service](../services.md#room-service), or the event
match service on an event table, gives to [01 Req](01.md). On a human table
it carries the rules and roster the players then confirm with `GameOK`; on
the Computer route the client polls it once and ignores the result. The
handshake is in [match-admission.md](../../flows/match-admission.md).

## 02/00 PLAYACK

| Direction | Service | Argument | Reply | Body |
| --- | --- | --- | --- | --- |
| S2C | room service to the requesting client | 0 | [41/08 GameOK](41.md#4108-gameok) from each human on a human table; none on the Computer route | `struct PLAYACK` |

```c
struct PLAYACK {
    int32_t EN;              // 1 accepted; negative values are refusals, see the table below
    struct {
        uint32_t bm;         // wager, 0..2000
        uint8_t  du;         // double-up flag
        uint8_t  st;         // special tiles flag
        uint8_t  cb;         // cb tiles flag
        uint8_t  ca;         // spinners flag
        uint8_t  gs;         // departure rule, 0..2
        uint8_t  tl;         // time limit, 0..5
    } Tet;                   // game rules, present when EN=1
    struct {
        uint8_t  in;         // observe setting, 0..2
        uint32_t lu;         // upper collection-point bound
        uint32_t ll;         // lower collection-point bound
        uint32_t au;         // upper rank bound, 300
        uint32_t al;         // lower rank bound, 100
        uint8_t  co;         // comment index, 0..8
        uint8_t  pa;         // 1 when a password is set
    } Tab;                   // table options, present when EN=1
    struct {
        uint32_t Num;        // member count
        uint8_t  MLNN[3][16]; // member names, hex bytes, `|` separated
        uint64_t MLID[3];    // member identities, `|` separated
        uint32_t Po[3];      // 0 in the known implementation (unverified)
        uint32_t Lv[3];      // collection points (unverified)
        uint32_t Rk[3];      // rating
        uint8_t  HN[3][16];  // handle names, hex bytes, `|` separated
    } GameML;                // roster, present when EN=1
};
```

```
S2C GTM0G02000000@PLAYACK=/EN=1@Tet=/bm=0/du=0/st=0/cb=0/ca=0/gs=1/tl=2@Tab=/in=1/lu=99999/ll=0/au=300/al=100/co=4/pa=0@GameML=/Num=2/MLNN=416C696365|426F62/MLID=0000000000000001|0000000000000002/Po=0|0/Lv=15|20/Rk=300|300/HN=416C696365|426F62
```

`Tet` and `Tab` are the rules `GameOK` accepts; a later Apply cannot change
them. The `GameML` section is the roster body of
[41/04 GameML](41.md#4104-gameml) without `/ID=`. The client keeps `MLNN`
and `HN` in 16-byte terminated fields, so a server must not send names
longer than 15 bytes.

Negative `EN` values the client maps to its own text:

| Reply | Meaning |
| --- | --- |
| `EN=-32870` | Table full |
| `EN=-32869` | Generic start failure |
| `EN=-32872` | Cancelled |

On an event table every seat receives a `PLAYACK` whose `Tet` and `Tab`
match the published table record; an observer receives the first seat's
`PLAYACK`.
