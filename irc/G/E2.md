# E2 TeachDVAns

The answer to [E1/00 TeachDV](E1.md#e100-teachdv): the client's file
locations and the identity of the [shop service](../services.md#shop-service)
it addresses for Init and the shop. Its place in the startup sequence is in
[startup.md](../../flows/startup.md).

## E2/00 TeachDVAns

| Direction | Service | Argument | Reply | Body |
| --- | --- | --- | --- | --- |
| S2C | service that received the TeachDV | 0 | none; the client continues with [80/00 Init](80.md#8000-init) | `struct TeachDVAns` |

```c
struct TeachDVAns {
    uint8_t D;              // profile directory of the player's files
    uint16_t V;             // profile volume of the player's files
    struct {
        uint8_t dir;        // directory
        uint16_t vol;       // volume
    } AC;                   // auction file location, dir|vol
    struct {
        uint8_t dir;        // directory
        uint16_t vol;       // volume
    } RK;                   // ranking file location, dir|vol
    struct {
        uint64_t id;        // shop service identity, 16 hex digits
        uint8_t dir;        // directory of the shop files
        uint16_t vol;       // volume of the shop files
    } Shm;                  // shop service identity and file location, id|dir|vol
};
```

```
S2C GTM0GE2000000@TeachDVAns=/D=1/V=1/AC=1|1/RK=1|1/Shm=0000000000000001|1|1
```

The reply must spell `@TeachDVAns=` with the equals sign. `D` and `V` become
the file owner of every later profile request
([service.md](../../file/service.md)) and the `Dm`/`Vol` of
[80/00 Init](80.md#8000-init). The `Shm` identity is the 64-bit game identity
whose scrambled nick the client addresses for Init and the shop.

Server choice: the values above are a minimal single-directory deployment;
the original service's values are not recovered.
