# 99 Event match reply

99 is the answer of the [event match service](../services.md#event-match-service)
to [98/00 EInitReq](98.md#9800-einitreq). What follows a positive answer is
in [event-matches.md](../../flows/event-matches.md).

## 99/00 EInitEnt

| Direction | Service | Argument | Reply | Body |
| --- | --- | --- | --- | --- |
| S2C | event match service | the sequence number of the request | none | `struct EInitEnt` |

```c
struct EInitEnt {
    uint32_t Card;        // 0 keeps the client's own five-card shortage check active; no other value is established
    int32_t  Ans;         // entry mode or denial, see the table
};
```

```
S2C GTM0G99000001@EInitEnt=/Card=0/Ans=1
```

| `Ans` | Meaning |
| --- | --- |
| 1 | playable entry, continues with [B2/13 EInit](B2.md#b213-init) |
| 2 | non-playing entry, see [event-rooms.md](../../flows/event-rooms.md#non-playing-entry) |
| -32870 | denied |
| -32872 | denied, excluded member |
| -32968 | denied, event finished |

With `Card=0` and fewer than five owned cards the client shows its shortage
dialog and does not proceed.

Server choice: a server answers `-32870` when the account is not
a member, not present in the room, before the event start, or busy in a
shop, trade or match; it never changes `Card` to bypass the shortage dialog.
