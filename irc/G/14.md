# 14 Apply

The owner's commit of the table settings editor, sent to the
[room service](../services.md#room-service). The editor sequence that leads
to it is in [tables.md](../../flows/tables.md#sequence);
its place in the start handshake is in
[match-admission.md](../../flows/match-admission.md).

## 14/00 Tet and Tab

| Direction | Service | Argument | Reply | Body |
| --- | --- | --- | --- | --- |
| C2S | room service | 0 | none | `struct Apply` |

```c
struct Apply {
    struct {
        uint32_t bm;      // wager, 0..2000
        uint8_t  du;      // double-up flag
        uint8_t  st;      // special tiles flag
        uint8_t  cb;      // cb tiles flag
        uint8_t  ca;      // spinners flag
        uint8_t  gs;      // departure rule, 0..2
        uint8_t  tl;      // time limit, 0..5
    } Tet;                // game rules
    struct {
        uint8_t  in;      // observe setting, 0..2
        uint32_t lu;      // upper collection-point bound
        uint32_t ll;      // lower collection-point bound
        uint32_t au;      // upper rank bound; the client always sends 300
        uint32_t al;      // lower rank bound; the client always sends 100
        uint8_t  co;      // comment index, 0..8
        uint8_t  pa;      // 1 when a password is set
        uint8_t  pw[12];  // password as hex byte pairs, present only when set
    } Tab;                // table options
};
```

```
C2S GTM0G14000000@Tet=/bm=0/du=0/st=1/cb=1/ca=1/gs=1/tl=2@Tab=/in=0/lu=99999/ll=0/au=300/al=100/co=8/pa=0
```

Both sections are always present, with the member layout of the same
sections in [24 Save](24.md). The client parses no reply: it closes the
editor as soon as the message is sent. After accepting an Apply a server
publishes the `TD` delta with the new metadata and owner, then
[41/04 GameML](41.md#4104-gameml) and [1A GameOwner](1A.md).

In a fixed room the client fills the Apply from the table metadata, so it
repeats the room's advertised rules exactly only when the server published
the same rules in the RL record and in the PTL metadata. The RL record alone
does not feed the outgoing fields.

Server choice: in a fixed room reject an Apply whose `Tet` differs from the
room rules; reject `au`/`al` other than 300/100, a password that does not fit
the metadata, and any Apply after a start offer or `Req`, because `PLAYACK`
and `GameOK` have already fixed the rules.
